# Objective

Deliver Project Membership Service Invariants for Phase 7C. The result must be directly usable by the next assigned coding agent without requiring that agent to invent architecture, schema semantics, service boundaries, or security rules.

# Context

Dynaxis owns Projects, Jobs, Assets, identity, graph, memory, orchestration, and verification. This Work Package is intentionally narrow: it must deliver Project Membership Service Invariants without reinterpreting the roadmap or absorbing adjacent package scope.

# Required Deliverables

- `ProjectMembershipService` server-only boundary
- membership create/update/remove/list/get operations for canonical `dynaxis_projects.id`
- typed service errors for project missing, workspace mismatch, non-workspace user, last-owner removal, and invalid role
- Verify the target project organization via 7C.4 ownership helpers before membership writes
- Require the user to be a Better Auth organization member of the project workspace for organization-owned projects
- Preserve at least one project owner and prevent demoting/removing the final owner
- Keep workspace roles and project roles separate; workspace `owner/admin/member/viewer` do not become project roles automatically

# Contracts That Must Not Change

- Dynaxis Project remains the canonical Project; do not create another Project entity.
- Better Auth remains the workspace authentication and organization-membership primitive.
- Provider credentials, model accounts, and worker adapters must not become user identity.
- Dynaxis Jobs, permissions, Project ownership, provenance, and verification gates must not be bypassed.
- Marketplace, App Factory, Skills, and Plugin work must use canonical registries instead of duplicating them.

# Acceptance Criteria

- Service rejects project membership for a user outside the owning workspace.
- Service preserves exactly-one personal workspace provisioning semantics.
- Service invariants are enforced before authorization packages consume memberships.

# Validation

- service tests for owner/admin/editor/viewer transitions
- concurrency/idempotency tests for invite or add retries where supported
- Run `npm run program:status` when Work Package metadata changes.
- Run `git diff --check` before handoff.

# Objective

Deliver Route Migration: Projects and Assets for Phase 7C. The result must be directly usable by the next assigned coding agent without requiring that agent to invent architecture, schema semantics, service boundaries, or security rules.

# Context

Dynaxis owns Projects, Jobs, Assets, identity, graph, memory, orchestration, and verification. This Work Package is intentionally narrow: it must deliver Route Migration: Projects and Assets without reinterpreting the roadmap or absorbing adjacent package scope.

# Dependencies

- WP-7C-13
- WP-7C-24 (Canonical Persistence Access Bridge) — integrated; WP-7C-14 consumes
  its canonical Workspace/Project-scoped Project and Asset store operations.

# Allowed Paths

- app/api/dynaxis/projects/**
- app/api/dynaxis/assets/**
- lib/dynaxis/services/projects.js
- lib/dynaxis/services/assets.js
- tests/dynaxis-platform-services.test.mjs
- docs/dynaxis/**

# Forbidden Paths

- unlisted lib/**, app/**, packages/**, drizzle/** paths
- unrelated roadmap phases
- canonical architecture rewrites
- PR creation or merge actions
- Provider Connections / Secrets runtime
- Developer Platform API credentials
- another Project entity
- Better Auth replacement

# Required Deliverables

- Projects routes migrated to AuthContext for list/create/get/update/archive while preserving Default Project behavior
- Assets routes migrated to project/resource authorization through canonical Project ownership
- standard not-found/forbidden behavior for cross-workspace Project and Asset access

# Contracts That Must Not Change

- Dynaxis Project remains the canonical Project; do not create another Project entity.
- Better Auth remains the workspace authentication and organization-membership primitive.
- Provider credentials, model accounts, and worker adapters must not become user identity.
- Dynaxis Jobs, permissions, Project ownership, provenance, and verification gates must not be bypassed.
- Marketplace, App Factory, Skills, and Plugin work must use canonical registries instead of duplicating them.

# Acceptance Criteria

- Project and Asset routes no longer parse legacy owner identity directly except through the route helper compatibility path.
- Cross-workspace asset/project access returns the expected 403/404 behavior without leaking ownership.

# Validation

- route/service tests for Projects and Assets with owner/admin/editor/viewer cases
- Run `npm run program:status` when Work Package metadata changes.
- Run `git diff --check` before handoff.

# Commit

Use a scoped commit message beginning with `docs(dynaxis)`, `feat(dynaxis)`, `fix(dynaxis)`, or `test(dynaxis)` as appropriate for the package. Include migration ownership, validation evidence, and any contract deviations in the final handoff.

# Stop Condition

Stop when the deliverables and validation above are complete. If an implementation dependency, migration-owner conflict, security issue, or architecture contradiction appears, stop and report it instead of broadening scope.

Deliver Authorization Vocabulary and Policy Specification for Phase 7C. The result must be directly usable by the next assigned coding agent without requiring that agent to invent architecture, schema semantics, service boundaries, or security rules.

# Required Deliverables

- permission vocabulary document for workspace, project, asset, generation, job, design, and admin actions
- policy boundary map separating workspace policy, project policy, and resource inheritance
- non-goals for Developer Platform credentials and Provider Connections
- Specification only; define inputs/outputs for later evaluator without editing runtime code

# Contracts That Must Not Change

- Dynaxis Project remains the canonical Project; do not create another Project entity.
- Better Auth remains the workspace authentication and organization-membership primitive.
- Provider credentials, model accounts, and worker adapters must not become user identity.
- Dynaxis Jobs, permissions, Project ownership, provenance, and verification gates must not be bypassed.
- Marketplace, App Factory, Skills, and Plugin work must use canonical registries instead of duplicating them.

# Acceptance Criteria

- Every permission has an owning domain and expected subject/resource inputs.
- The spec does not grant permissions from provider credentials or raw legacy API keys.

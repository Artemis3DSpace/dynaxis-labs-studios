# Required Deliverables

- `AuthContext` server contract with subject/principal, session, workspace, optional project, and permission projection
- session loader that uses Better Auth session and active organization
- compatibility projection for legacy ownerRef routes until migration completes
- Never pass raw Better Auth user/session objects into domain services
- Expose typed helpers for requiring workspace, requiring project, and checking permissions
- Represent anonymous, legacy, user, and future service-account subjects distinctly

# Contracts That Must Not Change

- Dynaxis Project remains the canonical Project; do not create another Project entity.
- Better Auth remains the workspace authentication and organization-membership primitive.
- Provider credentials, model accounts, and worker adapters must not become user identity.
- Dynaxis Jobs, permissions, Project ownership, provenance, and verification gates must not be bypassed.
- Marketplace, App Factory, Skills, and Plugin work must use canonical registries instead of duplicating them.

# Acceptance Criteria

- Every route can obtain one canonical AuthContext shape.
- AuthContext never treats provider API credentials as user identity.
